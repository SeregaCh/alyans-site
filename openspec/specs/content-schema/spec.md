## Requirements
### Requirement: Пять коллекций контента определены
Проект SHALL определять ровно пять коллекций контента: `napravleniya`, `obekty`, `dopuski`, `dokumenty`, `rekvizity`. Поля каждой коллекции соответствуют ТЗ §8 без добавления полей сверх ТЗ.

#### Scenario: Список коллекций
- **WHEN** запускается сборка и происходит разбор конфигурации коллекций
- **THEN** определены ровно пять коллекций: `napravleniya`, `obekty`, `dopuski`, `dokumenty`, `rekvizity`

### Requirement: Обязательные поля валидируются
Пропуск обязательного поля в записи любой коллекции SHALL приводить к падению сборки.

#### Scenario: Пустое обязательное поле
- **WHEN** запись коллекции не содержит значения обязательного поля схемы (например, у записи «Направление» отсутствует «название»)
- **THEN** сборка завершается ненулевым кодом с указанием на невалидную запись

### Requirement: Закрытые наборы значений — перечислением
Поля с исчерпывающим набором значений — направление объекта и тип допуска — SHALL валидироваться перечислением (enum) в схеме. Значение вне перечня обязано валить сборку.

#### Scenario: Опечатка в закрытом наборе
- **WHEN** запись объекта содержит в поле направления значение, не входящее в перечень трёх направлений (опечатка или новое значение)
- **THEN** сборка завершается ненулевым кодом с указанием на недопустимое значение поля

### Requirement: Открытые поля — свободный текст
Поля без исчерпывающего набора значений (наименование объекта, заказчик и аналогичные) SHALL принимать произвольный непустой текст без ограничения по перечню.

#### Scenario: Произвольное наименование
- **WHEN** запись объекта содержит новое, ранее не встречавшееся наименование в открытом текстовом поле
- **THEN** сборка не отклоняет запись по причине содержимого этого поля (при условии, что остальные поля валидны)

### Requirement: Копируемые значения — только обычные символы
Поля реестрового номера, ИНН, КПП, ОГРН, ОКПО, телефона и адреса почты SHALL отклонять типографские замены внутри значения: неразрывный дефис (U+2011), неразрывный пробел (U+00A0), длинное тире (U+2014) и среднее тире (U+2013). Допустимы только обычный дефис (U+002D) и обычный пробел.

#### Scenario: Неразрывный дефис в реестровом номере
- **WHEN** значение поля реестрового номера содержит символ U+2011 вместо обычного дефиса
- **THEN** сборка завершается ненулевым кодом с указанием на недопустимый символ в значении

#### Scenario: Неразрывный пробел в телефоне
- **WHEN** значение поля телефона содержит неразрывный пробел (U+00A0)
- **THEN** сборка завершается ненулевым кодом с указанием на недопустимый символ в значении
