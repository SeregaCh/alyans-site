## Находка и починка: заглушка `default_server`

При первом включении конфига (до сертификата) обнаружилось: незаданный Host-заголовок стал попадать на наш vhost вместо EasyPlan. Причина — `include sites-enabled/*` подключает файлы по алфавиту, «alyans-dev» читается раньше «easy-plan», и первый server-блок без явного `default_server` в файле становится перехватчиком незаданных хостов. Починка — отдельный блок-заглушка первым в нашем файле:

```nginx
server {
    listen 80 default_server;
    server_name _;
    return 444;
}
```

`444` рвёт соединение без ответа — ни наш сайт, ни чужой не отдаются на случайный Host. Проверено: `Host: неизвестный.example` → `curl: (52) Empty reply from server`; `Host: easy-plan.ru` — ответ EasyPlan как раньше.

Второй найденный и тоже сразу починенный дефект того же захода: `try_files $uri $uri/ /404.html;` отдавал страницу 404 с кодом **200** (URI-fallback на реальный файл — не ошибка, а обычный успешный ответ). Правильная связка — код рождается по-настоящему:

```nginx
location / {
    try_files $uri $uri/ @notfound;
}
location @notfound {
    return 404;
}
error_page 404 /404.html;
location = /404.html {
    internal;
}
```
