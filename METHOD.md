# Методология разработки — МАСТЕР
> Синхро-копия канона. Источник: METHOD(MASTER) v2.2 от 2026-09-09. Дата синка: 2026-09-11. В репозитории не правится — правки приезжают от мастера.


Версия 2.2 · 2026-09-09 (в2.2: патч по обкатке v2 — 48 записей · сторож размеров — четыре файла · ведение ROADMAP · гейт закрывает назначивший · правила продукта ≠ правила агентов · отметка = факт). Предыдущий: 2.1 · 2026-08-19 (область сторожа именным списком · физические писатели git · стартовая сверка знаний), патч по обкатке v1 (156 записей, 37 адресовок) и решениям автора 2026-08-18/19.

Переносимая схема работы, не привязанная к проекту. Всё проектное — в `PROJECT.md`; надпроектные конвенции кода и данных — в `CONVENTIONS.md` (мастер, синхро-копия в каждом репо); проектные — в `openspec/config.yaml` (рождается на этапах 4–5: CONVENTIONS + проектный блок по приложению A6 GRANDROADMAP); механика разрешений сервера — в `.claude/settings.json` проекта. Канон — только этот мастер; в репозиториях проектов — синхро-копии с шапкой и датой синка, там не правятся.

Файл трёхслойный (решение автора 2026-08-17): **ЖЕЛЕЗО** — короткий блок, который любая сессия держит наизусть; **рабочие разделы** — режим текущей работы; **СПРАВОЧНИК** — читается адресно, по надобности, не целиком.

## 0. ЖЕЛЕЗО (наизусть, любой агент, любая сессия)

1. **Слово автора о факте и его практике = факт.** Опровергать — только проверкой за минуту, со следом (история git, статус-страница, вывод команды). Прежде чем объявить нарушение — искать следы.
2. **Дешёвое действие раньше рассуждения.** Перед тем как строить объяснение — повторить вызов, открыть документацию, прочитать строку кода. Догадка называется догадкой; «наверное там» = сигнал идти в разведку, не писать дальше.
3. **«Проверено» = есть след** (вызов, вывод, хеш, коммит, скрин). Без следа это «поверил отчёту» — так и называть. Проверка обязана валить ошибку, а не печатать «ок»; после починки — перепроверка с нуля. Отметка «сделано» ставится ТЕМ ЖЕ действием, что создаёт файл или факт — не позже, по памяти о намерении. Ответ агента «сделал» без наблюдаемого признака — не факт, даже для безобидного действия. Живое проверяется процессом, который обслуживает интерфейс, не отдельным скриптом; после apply — рестарт и проверка на живом («проверено на одном, запущено другое» — пять случаев).
4. **Область действия.** У любого утверждения, правила и ослабления есть явная область. Выход за неё — вопрос, а не вывод. Ослабление, выданное для X, не распространяется на соседнее Y без отдельного слова.
5. **Один такт за раз.** Одно сообщение одному агенту → дождаться ответа. Одна задача за раз; в живом гейт-режиме одно сообщение = одна команда. **Всё переносимое между агентами — только код-блоком, первая строка — адресат («→ Кому»); без адресата и прозой не выдавать. Автор промптов не сочиняет и не читает — блок обязан быть самодостаточным: имена из PROJECT/DESIGN, не плейсхолдеры.** Блок, выданный автору, означает: решение принято; подтверждение спрашивается ДО блока отдельной строкой и никогда внутри него.
6. **Стоп вместо интерпретации.** Расхождение плана, дизайна, данных и кода — остановка и вопрос, не «переосмысление». Молчаливая подмена смысла = рисковая команда.
7. **Гейты и чек-листы — вслух**, пункт за пунктом, с подтверждением. Молчаливый проскок = дефект, даже если всё «и так очевидно».
8. **Правило живёт там, где действует.** Переводимое в код или настройку — переводится (лучшее правило нельзя нарушить); текст без механизма = пожелание. Текст промпта модели — гипотеза о поведении, не гарантия: запрет буквой обходится буквой; механизм — первый слой, текст — второй, проверка — живой пробой. Сомнение, к какому классу риска относится шаг → красный (fail-closed).
9. **«Разрешено молчанием» не существует.** Нет ответа, права, подтверждения — исход «отказ», никогда «действие». Направление fail-closed — та сторона, где слово автора остаётся за автором: молчание перед началом работы = не работать, молчание перед необратимым = не делать; цена ошибки асимметрична, направление выбирается по ней, не по привычке соседнего места.
10. **Обзор готового мира — обязательный шаг** этапа идеи/ТЗ и каждой крупной области. Час ландшафта раньше месяца стройки; строить своё — решение после обзора, не вместо него.
11. **Граница среза — критерием, не списком:** в срез входит всё, без чего его механизм не даёт положительного исхода, и ничего, что строит новый механизм. После второго уточнения границы за срез — вопрос себе вслух: «граница держится или закапываемся?»; третье уточнение = граница проведена неверно — пересобрать, не уточнять дальше.
12. **Память в файлах, не в контексте.** Правила ведения файлов (раздел 4) — часть железа. **Физически пишут в git только сервер (по блокам) и Design в своей зоне (`docs/design-drafts/**`); чат-агенты правок в репозиторий не делают — их правки едут блоком серверу. Автор руками файлы не переносит (слово автора 2026-09-09): синхро-копии канона едут серверу блоком-скриптом правок, не файлом.**

## 1. Роли

Режим ниже — **текущий**: разработка идёт руками автора между агентами. Что из этого умирает после релиза Пульта — раздел 3.

**Правила строящегося продукта ≠ правила агентов.** Спецификация поведения продукта (например, где встроенный архитектор Пульта обязан остановиться и спросить автора) — не регламент чата; чат-агент к себе её не применяет и лишних тактов подтверждения не плодит.

**Чат-архитектор (Opus)** — планирует, формулирует, ревьюит, решает; кода не пишет.
- Рассуждать, а не перекладывать: на развилке — рекомендация с обоснованием. Вопрос автору — крайнее средство и только продуктовый (как должно себя вести), не про устройство кода.
- Не гадать: о коде — разведка (мелкую делает сам из репозитория коннектором; к серверу — за живым окружением); о вкусе — направление от автора; о форме артефакта — шаблон из приложения GRANDROADMAP (нет документа — попросить, не начинать).
- Перед пропоулом и ревью — перечитать живые файлы из git, не полагаясь на версию из начала чата. Рез ставится от документа-источника цели (ТЗ, DESIGN, DECISIONS), не от заголовка пункта плана: название пункта очереди — не цель.
- «Кто физически исполняет шаг и может ли» — к собственным поручениям агентам так же, как к чужим планам.
- Такт обслуживания файлов (уборка, сверка бухгалтерии) — не движение по плану; второй такт обслуживания подряд называется вслух, продолжать ли — решает автор.
- Ответ на вопрос-выбор автора = одно слово/буква; обоснование — по запросу или при явном риске.
- Замечание ревью, утверждающее поведение («пользователь увидит X»), требует открытого файла, который это поведение реализует.
- Рабочие очереди и наблюдения — в файл сразу по факту, не копятся в голове до конца такта.

**Claude Design (отдельный чат)** — весь UI по `DESIGN.md`.
- Драфт-цепочка (все команды сочиняет архитектор, автор утверждает вкус): бриф → концепт → вкус автора → закрывающий промпт → дельта → «прими как драфт» (сервер пишет `DESIGN.draft.md`) → ревью архитектора → «финализируй». Команда финализации не существует до ревью.
- При ревью драфта архитектор спрашивает вслух: есть ли текст, который в `DESIGN.md` не идёт, но должен пережить финализацию (→ `DECISIONS`).
- Зона записи Design в репо — `docs/design-drafts/**`; сервер читает, не правит: упёрся в непокрытое дизайном — возврат к Design за дополнением, не самодеятельность. Граница «кто пишет какой UI-код» фиксируется при первом реальном заходе.
- **Не гадать о вкусе:** заход не начинается без направления от автора — референсы (2–3 интерфейса), готовая система или хотя бы прилагательные; нейтральное «на свой вкус» не выдавать. Новые токены/паттерны — только явным предложением в `DESIGN.md`, вторую систему не изобретать.
- **Визуалы (HTML/картинки) — аргумент для глаз автора при утверждении вкуса, в git не едут**; артефакт захода — текстовая дельта для `DESIGN.md`.

**Сервер (Claude Code на VPS)** — исполнитель: код, сборка, миграции, деплой, read-only разведка.
- Читает `CLAUDE.md` проекта при старте; классы подтверждений и их механика — там и в `.claude/settings.json` (мастер их не дублирует — второй источник истины дрейфует).
- «Закоммичено» ≠ «запущено»: рестарт/подхват — часть шага; «работает» доказывается на живом процессе, не на факте коммита.
- Дефект или долг, найденный по ходу apply, немедленно становится строкой tasks — иначе «всё закрыто» его не включает.
- Обновление модели/инструмента — между задачами, на чистом дереве, только решением автора; **первая задача на новой версии — с усиленным ревью**. Класс модели исполнителя не поднимается по умолчанию — только при стабильных промахах на корректных промптах (мышление — у архитектора, исполнение — на сервере).
- Рабочая копия не живёт впереди git дольше одного шага: «сборка чистая» без коммита — не прогресс, а незафиксированный риск.

**Автор** — решения, вкус, проверка живого. Переносит готовые блоки между агентами (до релиза Пульта); промптов не сочиняет, руками рутину не делает — если план поручает автору ручной шаг, это сигнал проверить, не делает ли его инструмент.

**Ревизор (внешний, надпроектный)** — методолог мастера и внешний ревьюер; проекты по циклу не ведёт.
- Зовут: гейты этапов · [крит]-области · первый случай нового класса · развилка к автору · разворот охвата посреди работы.
- Читает артефакты сам из git; в репозиторий не пишет. Вердикт «закрыто/доказано» — только после собственного чтения репозитория тем же тактом; отчёт агента — повод читать, не основание подтверждать. Блок Ревизора — после перечитывания ROADMAP тем же тактом.
- Гейт назначает Ревизор — исход принимает Ревизор; отчёт архитектора о собственных удачных пробах — повод читать, не основание закрыть рез.
- Рамку принесённого вопроса Ревизор проверяет на полноту сам, перечитав документ-источник цели; узкий вопрос не даёт права на узкий вердикт.
- Тренд из трёх резов одной формы (клетка уплотняется, «опять то же самое») — пересмотр рамки Ревизором, не ожидание слова автора: дрейф складывается из локально верных резов и ловится только этажом выше.
- Классом модели не слабее ревьюируемого архитектора.
- Порядок ревью: пропоулы — сервер → архитектор → Ревизор → автор; отчёты apply — сначала архитектору; надпроектное — Ревизор до архитектора.
- Грань решений: устройство/канон/периметр — Ревизор; продукт и вкус — автор; резы срезов — архитектор.

## 2. Цикл, разведка, темп

**Цикл одной задачи:**
1. Архитектор берёт пункт ROADMAP; UI-задача — сперва дизайн-заход.
2. **Разведка** — если задача трогает существующее (код, данные, живое окружение): read-only, фактами, до проектирования; запрос — дословный (какие сущности/обработчики/связи показать), ответ — релевантными кусками кода, не пересказом. Не трогает — пропоул обязан сказать это явно («существующего не трогает»); молча пропустить шаг нельзя. Признак обязательности: в рассуждении появилось «наверное / скорее всего там».
3. `propose` → сервер генерит артефакты и сразу коммитит их папку — архитектор читает из репозитория.
4. Ревью против источника (план — против ТЗ/DESIGN, реализация — против плана), краевые: `null` и пустые состояния · двойные загрузки/эффекты и что перезагружает каждый обработчик · самоконфликт при редактировании (исключение себя) · краевые во времени (наследование периодов, правка задним числом) · содержимое против габаритов · **кто физически исполняет каждый шаг и может ли** (права, доступ, TTY) · **чем инициируется каждый живой шаг и существует ли триггер** · для кода на чужой машине — шаг доставки и живой проверки там · **против образа:** какую строку мерила (ТЗ, целевой цикл) рез приближает и не добавляет ли состояние, которого в образе нет — нет ответа, возврат; гейт проверяет рез против его цели, вопрос о картине целиком задаёт только этот пункт.
5. `apply` → код и тесты. Apply завершён = закоммичено и запушено; правки поверх — тем же тактом. Рисковое — по классам из `CLAUDE.md`/settings; «don't ask again» запрещён всегда.
6. Живая проверка — поведением, не глазами: счёт запросов, состояние, логи; кратковременное состояние — условия наблюдаемости фактом до захода; сработал именно проверяемый путь, а не посторонний барьер.
7. **Развороты охвата — норма, но фиксируются явно:** факты (разведка, живая проверка, слово автора) поменяли масштаб — переписать пропоул, не растягивать молча; сделанное стало промежуточным шагом — отметить в ROADMAP.
8. `archive` → синк спеки; правила дельт — `CONVENTIONS.md`, раздел 4 (здесь не дублируются). Ошибочный change не архивируется — archive означает «это правда о мире»; ошибочное снимается с записью причины. Условия закрытия реза формулируются машинно проверяемыми там, где это возможно (команда, счёт, множество до/после); «проверено глазами» допустимо только там, где машинной формы нет, и это названо. Чек-лист файлов вслух: рез снят из очереди и вписан в закрытые? · паспорт среза в log/? · DECISIONS? · DESIGN? · CHANGELOG? · ОБКАТКА?

**Разведка исполнимости** (права, окружение, триггеры) — часть ревью плана, не реакция на блокер.

**Регрессионная сеть:** критические потоки (пометка `[крит]` в ROADMAP — авторизация, запись данных, барьеры) покрываются автотестами по мере появления; регрессия гоняется при каждом apply и релизе. Не «тесты на всё» — страховка, что новая фича молча не ломает старую: новое проверяют руки, старое стерегут автотесты. «Полная регрессия» для проекта из нескольких половин (клиент/сервер) — все половины одной командой или каждая названа явно, не подразумевается; замечание ревью о поведении кода требует его прогона, не только чтения.

**Темп и форма** (очерёдность — железо-5): задача — короткая и ясная, не эпик; лаконичность — вердикт + блок, «почему» кратко и при риске; переносимое — код-блоком с адресатом первой строкой (`→ Кому`), без адресата не выдавать, прозой не выдавать. Язык всех агентов — русский, строка о языке — в рабочем файле каждого агента.

**Фазы:** до-репозиторная (артефакты и входы руками — штатный фолбэк; не-целевые репозитории коннектора не читать и не наследовать) / зрелая (git-логистика, агенты читают живые файлы сами). **Фаза определяется наличием репозитория**, не ярлыком этапа; указатель позиции — мутабельный (статусная строка ROADMAP + состояние репо), в прозу не зашивается.

## 3. После релиза Пульта (включается отдельным патчем при релизе; до того — ориентир)

Умирает: перенос блоков автором · подтверждения в терминале (1/2/3) · копипаста файлов и отчётов.
Заменяется каналом Пульта: задачи исполнителю — человеческим текстом, отчёты — обратно, всё — в ленте.
**Три этажа решений:** машинное рутинное — разрешено настройкой, едет молча · вопросы по ходу работы — решает архитектор сам (permission-цикл, блокирующий машинный сигнал) · необратимое поимённо (прод, деньги, наружу) — карточка автору. **Граница карточки = граница человеческого решения.**
Память среза — у Пульта (resume сессий архитектора и исполнителя); лента и журнал — append-only след; закон экономии токенов: на развилках «дороже разово / дешевле в ритме» выбирается дешевле в ритме.

## 4. Правила ведения файлов (железо)

1. **Один файл — одна роль:** ROADMAP — план (что дальше) · `log/` — что было · PROJECT — как устроено сейчас · DECISIONS — почему решили · METHOD — как работаем. Запись, не отвечающая на вопрос файла, в него не пишется.
2. **Живой служебный .md: ≤500 строк и ≤40 КБ.** Упёрся — делить или выжимать сейчас; полное — в архив, читаемый адресно.
3. **Лимит проверяется машинно:** сторож размеров в регрессии — закрытый именной список файлов, которые агент тянет в контекст на КАЖДОМ старте: ROADMAP, PROJECT, DECISIONS, CLAUDE.md; байты И строки; превышение = красный прогон. Вне сторожа: синхро-копии канона (лимит держит мастер-процесс) · IDEA/ТЗ/DESIGN (DESIGN при росте называется сигнальной строкой такта) · ОБКАТКА — между патчами мастера читается адресно, целиком только как вход патча, лимит веса ей не нужен (решение автора 2026-09-09). Именной override предела одному файлу — только решением автора и только по содержательному критерию («лишнего нет — расширяем, есть — чистим»); пофайлово, соседям молча не достаётся (железо-4); лимит строк override не получает.
4. **DECISIONS-запись:** дата · что решено · кем · одна строка «почему» · что отвергли. 3–5 строк. Развёрнутое обоснование — в паспорт среза в `log/`, здесь ссылка.
5. **PROJECT — только настоящее время.** Предложение с датой и глаголом прошедшего времени едет в `log/`, не сюда.
6. **Доказательства фактом** (суммы, отказы, прогоны, хеши) — в паспорте среза в `log/`. В ROADMAP и PROJECT им места нет.
7. **Закрытие среза:** паспорт целиком уезжает в `log/ГГГГ-ММ-ДД-имя.md`; в ROADMAP от среза остаётся строка в сводке.
8. **Архив в контекст сессии целиком не тянется** — только адресно, по конкретному вопросу.
9. **Синхро-копии канона** (METHOD, CONVENTIONS, GRANDROADMAP) — правки мастера едут серверу блоком-скриптом (каждая замена — точное единственное совпадение, иначе стоп); сервер применяет к копии в репо, обновляет дату и версию в шапке, сверяет невидимые символы. Целый длинный файл через контекст агента не гоняется.
10. **Писатель в файл** — один на файл (или явный протокол передачи): у каждого живого файла назван ведущий. «Ведёт» = отвечает за содержание; физическую запись в git делает сервер (железо-12). Параллельная правка одного файла двумя агентами запрещена.
11. **ROADMAP:** мерило файла — автор открывает «Порядок дальше» и без ключей, без другого документа видит, какие резы идут дальше; не выполняется — файл дефектен, сколько бы правды в нём ни было. Раздел отвечает на свой вопрос: очередь — только очередь; хроника, обоснования, доказательства — в `log/`, DECISIONS, архив. Имён два — область и рез; нумерация паспортов и спек наружу не выходит; имя нового реза берётся из паспортов `log/` машинно (максимум), не по памяти. Одна очередь на файл — вторая бухгалтерия удаляется, не сверяется. Закрытый рез снимается из очереди тем же тактом, что вписывается в закрытые. Уборка проверяется вопросом «стало ли сущностей и разделов меньше», не «объяснены ли они» — легенда лишней схеме продлевает жизнь и выглядит как порядок. Правка по перечню мест не проверяет роль раздела — роль проверяется отдельным проходом. **Строка «Сейчас:»** — в ROADMAP любого проекта единственное место, где живёт текущий рез: имя реза · состояние · что следующее; обновляется вручную при смене реза; агент и Пульт её читают и показывают, не хранят копии.
12. **Пометка `[ВРЕМЕННОЕ]`** в любом файле обязана иметь строку в очереди ROADMAP тем же тактом; без неё это текст, не работа.
13. **Списание механизма с заменой:** запись DECISIONS «отменяем X, замена — Y» ставит Y строкой ROADMAP тем же тактом — позитивное требование внутри записи «что отменяем» иначе теряется.

## 5. Безопасность (принципы; механика — в файлах проекта)

- **Страховка нестираема тем, от кого страхует:** бэкапы — вне досягаемости исполнителя (право «только класть» с его машины); запрет переписывания истории — на стороне git-сервера. Обе — до первой боевой работы, проверены фактом отказа.
- **На машинах с исполнителем не бывает ключей шире одного репозитория.** Deploy-ключи узкого scope; ключ аккаунта там не лежит. Учёт ключей системы (SSH, deploy, токены, сертификаты) — одним списком со сроками; после переавторизации проверять полноту доступа, не факт.
- **Правила прав исполнителя — только из кода/настроек управляющей стороны.** Файловый источник правил в зоне записи самого исполнителя = правило, редактируемое подсудимым; исключается изоляцией.
- **Машинный сигнал вместо текст-эвристики:** различение исходов (вопрос / отчёт / отказ / успех) — механизмом протокола; эвристика по формулировке запрещена как класс.
- Бэкап перед необратимым, ненулевого размера; папка бэкапов не в git. Миграции — только вперёд; уникальные ограничения — после разведки дублей. Секреты — не в argv **и не в вывод**: из конфигов извлекается только нужное поле.
- **Откат (revert-play):** apply пошёл не так — стоп → оценка → откат к рабочему коммиту (+БД из бэкапа шага) → причина в запись → чистый повторный заход. Полурабочее не коммитится.

## 6. Старт чата и переезд

- Роль и правила — из знаний Project; проектный контекст — из инструкций. **Стартовый ритуал: сверить дату синка METHOD в знаниях с датой синхро-копии в репо; расхождение → истина в репо, доложить автору до работы.** Первое сообщение автора — сразу дело; агент определяет фазу, пересказывает состояние, ждёт подтверждения.
- Чат — расходник: память живёт в файлах. Переезжать **до** деградации; признаки — растущий счёт ошибок, потеря решений. Тяжёлые вердикты при подозрении на пониженную модель не выносятся.
- Перед переездом — сброс в файлы: «всё ли существенное зафиксировано в ROADMAP / log / DECISIONS / DESIGN; незафиксированное — дозаписать». Выжимка при переезде собирается **с открытым источником**, дифф глазами — не по памяти; сжатие проверяется на слияние двух состояний в одно (сжатие воскрешает снятое). Утверждение о состоянии кодбейза проверяется репозиторием, не памятью и не авто-сводкой переполненного контекста. Без коннектора (фолбэк) — приложить к первому сообщению ROADMAP, PROJECT и METHOD руками.

## 7. СПРАВОЧНИК (адресно; не для заучивания)

### 7.1 Принципы-прецеденты (копилка; каждый куплен случаем)
- Место находки ≠ принадлежность; факт инструмента ≠ факт мира (версия — часть факта); рассуждение ≠ факт.
- Терминальный статус — обещание об исходе из проверенного состояния; честные состояния: текст статуса различает причины («упала» ≠ «заблокирована до старта»).
- Право без доказательства не выдаётся; право командного класса = множество путей записи, снятое фактом; «поимённо и узко» ≠ «произвольно»; утверждение об отсутствии действий проверяется следом так же, как о действии.
- Тот же код ≠ тот же смысл; инвариант выхода живёт в функции выхода целиком; новая забота — новый модуль, вызывающий код только вызывает; «открывает вычисленное — контракт, добавляет вычисление — забота».
- Расширение решения не расширяет автоматически код, опиравшийся на старую версию — ревизовать всех, кто ссылался.
- Правда о механизме принадлежит срезу, где механизм построен (конверт, описывающий старый мир — ложь новому).
- Синоним опасной формы опасен; у фонового действия два адресата; счёт касаний — корзинами с актёрами поимённо.
- Сырьё ответа агента (usage, вердикты, вход) сохраняется как есть, поля не выбираются поимённо — завтра не хватит другого поля.
- Ссылка на артефакт — по имени/заголовку, не «см. файл»; проверяемая ссылка ловит ненаписанное.
- Расхождение источников чинится в источнике немедленно, не комментарием на ревью.
- Атрибуция источника: факты с чужой машины сервер не видит — в записи называется, кто наблюдал.
- Такт закрыт = есть отчёт; шаг живого гейта называет состояние общих ресурсов, в котором оставляет стенд.
- Вопросы автору: субъект+действие, нейтральный пересказ, не подсказанный ответ — для архитектора так же, как для карточек.
- Ручные id в БД — только форматом приложения (генератор), не литералом «на глаз».
- Сторонний пакет шумит в вывод — шум/сигнал разделять при разборе логов.
- Номера строк в артефактах устаревают — работать по фактическим определениям, не по номерам.
- Долг закрывается снятием пути, не дефекта — только названным: форма допустима, если в плане не остаётся пути к дефекту и документация не врёт.
- Давая агенту механизм, промпт пишет обязанность («делай сам»), не наличие («у тебя есть») — механизм без указания не используется.
- Картинка = код: дефект по скриншоту объявляется после дешёвого действия, не по виду.
- Правка по перечню мест — после машинного прохода по всему файлу (grep) ДО правки; список ловит названное и не ловит остальные вхождения.
- `/clear` и новая сессия — рука автора в терминале; изнутри сессии агент себя не очищает.

### 7.2 Жаргон
пропоул (план изменения) · apply (реализация) · срез (единица приёмки с паспортом) · такт (один обмен с агентом) · гейт (проход чек-листа вслух) · плашка (отчёт агента) · фолд (свёртка контекста) · руки (право исполнять) · клетка (ограничение исполнителя механизмом).

### 7.3 GitHub-коннектор (боевая инструкция)
Подключать из браузера claude.ai: Settings → Connectors → Add custom connector → Name `GitHub`, URL `https://api.githubcopilot.com/mcp/`, OAuth-поля пустые → Connect → Authorize (дождаться редиректа). Затем обязательно выдать доступ: github.com/settings/installations → Claude GitHub MCP Connector → Configure → Only select repositories → добавить репозиторий → Save (иначе 404 на приватных). В Desktop коннектор появляется после перезапуска приложения и только в новых чатах; в промптах указывать реальную ветку. Не путать со штатной «GitHub Integration» (ручное прикрепление) — сосуществуют.

### 7.4 Проверка живого — памятка
После пересборки — жёсткая перезагрузка (кэш меряет старый код). Где загрузка данных — счёт запросов (1–2, не поток; тихий цикл маскируется успешными ответами). Браузерный агент — точечно, для невидимого глазом; рутину проверяет автор быстрее.

### 7.5 Обкатка
`ОБКАТКА.md` — временный лог трения о методологию: строка на случай (дата + что мешало/где система не спасла). Трение — это: пришлось сделать лишнее · система не спасла от ошибки · правило непонятно или забылось · реальность разошлась с документами. Автор фиксирует сразу; DECISIONS — про продукт, ОБКАТКА — про метод. Мерило ранжирования правил при патче мастера — счёт нарушений, не ощущение. После патча мастера файл обнуляется, том уезжает в `docs/archive/`. Полнота выходов патча — машинно: число записей тома равно числу строк реестра домов (запись → правило или объяснение); расхождение = патч не закрыт.
